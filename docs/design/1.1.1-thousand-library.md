# 1.1.1 播放页与千首曲库修复

2026-10-15。范围为现有 Android 原生 App，当前 main 分支，本地提交，不推送。iOS 和网页候选方案不改。

## 可检查的目标

- 原版 B 封面画廊继续固定，扩大封面的可用宽度与最大尺寸；先给一行歌词保留空间，再用剩余高度安排封面。
- 长歌词单行横向滚动完整展示，字体与主题设置沿用；完整歌词页仍保留纵向滚动。
- 进度条左侧为已播放时间，拖动时显示目标时间；右侧恒为歌曲完整时长，优先使用播放器时长，未取得时使用标签时长。
- 约 1000 首场景下，避免在主线程读取曲库、反复序列化全量数据、解码大封面和重复计算排序。保留手动刷新重读所有标签及文件增删改的规则。

## 已定位的问题与修改

| 路径 | 原因 | 修改 |
| --- | --- | --- |
| 启动 | Repository 构造时同步读设置；Service 又同步读取全部曲库 | 默认状态立即返回，后台初始化，界面等待 ready；服务复用已加载曲库，后台读取保存队列，用户新操作优先 |
| 收藏、歌单、排序、歌词设置 | SharedPreferences.apply 之前的 JSON 序列化仍在 UI 线程 | 单个合并请求的 IO 写入者，按变更字段序列化；初始化与备份恢复共享持久化互斥锁 |
| 添加文件 | 逐文件反复查找、过滤整个曲库；批量授权也在 UI 线程 | Map/Set 批量合并与后台授权；新增文件夹只扫描本次选择的文件夹，手动刷新仍全量读取 |
| FLAC | 重复经 MediaMetadataRetriever 提取大封面；未知块和 padding 分配大数组 | 直接读取 FLAC 标签块，未知块使用有界缓冲跳过；封面内容分块比较 |
| 封面列表 | 重复解码；歌单缩略图按大图尺寸读取；切歌短暂保留上一张图 | 共享有字节上限的 LRU、最多两个并行解码、按展示尺寸采样、内容版本键和键变化重置状态 |
| 排序与搜索 | A–Z 排序阻塞 UI；部分分组和拖动每帧重复建表 | 排序与拼音索引在 Default 后台构建，未准备完显示等待状态；缓存分组与拖动 ID 列表 |
| 队列 | 批量元数据逐首提交；同步序列化队列；极端反序排序集中执行 | 连续区段合并更新、合并 timeline 回调、后台序列化队列、移动操作按约 4 ms 预算让出主线程；新队列/手动编辑终止旧排序 |
| 数据一致性 | 重复歌曲 ID 与排序 ID；SQLite replace 改变 rowid 顺序 | 稳定去重、首个排序位置优先、现存行使用 UPDATE；事务取消回滚 |
| 批量撤销 | 为每个被删除成员重新扫描和复制整个歌单 | 常规原顺序子序列按一遍合并恢复；后来重排/新增场景沿用邻居锚点规则 |
| 备份 | JSON 生成发生在主线程 | JSON 生成与输出写入均放 IO |

Media3 实例的访问和播放指令继续在主线程；队列排序使用 move 操作，保留当前歌曲与进度，不通过重新设置整条队列实现排序。长队列移动可能跨几个调度周期完成；用户切换队列或手动编辑时终止旧任务。

## 自动检查范围

新增 JVM 场景使用 1000 个 Song 数据对象：重复扫描、标签更新、来源与顺序合并、随机/自定义排序、播放队列移动计划、批量添加/删除/撤销、搜索索引复用和取消。FLAC 测试覆盖大 padding 和截断未知块。

新增 Android 仪器用例覆盖：1000 条数据初始化与快速修改时不在主线程访问偏好、恢复后的最终写入一致性、1000 条标签更新保持顺序及取消事务回滚、封面尺寸/版本/缓存/失败重试。播放页用例更新为单行完整文本与总时长标签。仪器用例本轮仅编译，未在设备执行。

桌面 JVM 基准只测“从空歌单撤销恢复 1000 个成员，并恢复随机顺序”。相同输入先预热 15 次，再测 30 次；本次复测中位数从 35.772 ms 降至 0.442 ms，p95 从 40.693 ms 降至 0.856 ms。它不代表整款 App 加速比例、导入吞吐或手机帧率。

最终编译、单元测试、Lint、签名与资源结果见 [APK 检查](../../dist/小红花-1.1.1-CHECK.json)、[仪器测试状态](../../dist/ANDROID-1.1.1-UI-CHECK.json) 和 [千首检查记录](../../dist/ANDROID-1.1.1-PERFORMANCE-CHECK.json)。

## 仍需设备验证的边界

按用户选择，本轮先完成修复与自动检查，不要求连接手机。尚未实测小米 15 上 1000 个真实 FLAC、实际 100 GB 文件夹、SAF 提供者读取速度、峰值内存、动画帧率、通知/锁屏和后台恢复。无法把桌面单元测试或原生测试编译当成“所有手机绝不卡顿或无 Bug”的证明。

后续设备验收应使用本人真实文件夹：首次导入时同时滚动与切页；手动刷新同字节大小/同时间戳的标签和 LRC 变化；千首快速搜索和排序；大歌单批量增删撤销；倒序保存时确认当前歌/进度/模式与下一首；持续滚动观察封面与内存；前后台和重启后恢复；小屏/大字号下一行长歌词与总时长显示。
