# 小红花 Android · 1.0.1

原生 Kotlin / Compose / Media3 本地音乐播放器。保留 `../ui/` 作为设计参考；本工程生成真正的安卓 APK。源码已准备开源，正式签名密钥仅保存在本地。

## 安装与使用

安装包：[下载小红花 1.0.1 APK](https://github.com/xymw54128/Little-Red-Flower-Music-Player/releases/download/v1.0.1/%E5%B0%8F%E7%BA%A2%E8%8A%B1-1.0.1.apk)，约 44 MB / 41.70 MiB（包含内置中文字体）。沿用旧版的应用 ID 与签名，直接覆盖安装，保留现有数据。本地已有安装包仍位于 `../dist/小红花-1.0.1.apk`；Git 克隆不包含 APK，请从 Release 下载。

1. 将 APK 传到小米 15，在手机文件管理器中打开并安装。手机可能要求为文件管理器允许安装此应用。
2. 打开小红花，点音乐库右上角 `+`，选择音乐文件，或授权音乐文件夹。文件夹递归扫描，音乐原文件不复制、不修改。
3. 点歌曲开始播放；底部迷你播放器进入完整播放页。封面左滑查看歌词，歌词右滑返回。
4. 歌曲菜单可选择目标歌单再确认添加。排序菜单中的自定义顺序需保存才生效。
5. 歌单列表或歌单右上角的相册按钮可更换封面，支持 8 种图案和系统相册照片。设置可调整歌词、颜色和背景；文件夹页的刷新会强制重读标签。导出备份后，将音乐文件、背景与歌单照片另行保管。

支持范围：最低 Android 8（API 26），目标 Android 16（API 36）；APK 包含 ARM64、ARMv7、x86、x86_64。1.0.0 已由用户验收；1.0.1 的新增交互与启动动画仍需手机验收。

- 原顶部进度条来自每 5 秒监测的 `busy` 状态。现在忙碌状态和用户可见反馈分开；自动监测、提供者通知及前台检查静默同步，用户导入/添加文件夹/手动刷新保留进度提示。仍保留文件增删改和标签刷新。

## 0.1.3 调整

- 歌词从“到时间戳后启动 560 ms 滚动”改为按实际播放位置逐帧计算轨迹。最长约 480 ms，短间隔按相邻时间戳缩短；通常在下一行时间戳前 24 ms 完成居中，高亮仍按时间戳切换。没有过期动画队列。暂停冻结、跳播直接定位，手动浏览停止 4 秒后恢复跟随。仅歌词页可见且应用前台时运行帧循环；不向整个界面发送逐帧状态。
- 移除歌词逐行的 360 ms 颜色和缩放动画，避免高亮滞后与多余重绘。按实际排版高度处理长歌词、译文与字体切换。屏幕每帧按真实时间追赶；间隔小于一帧或系统掉帧时，不能保证显示所有中间行。尚未在手机测量帧率。
- 默认封面提供红花、森林、海浪、月夜、暖阳、唱片、耳机和钢琴，新歌单优先使用当前较少出现的图案，旧歌单加载时补充并保存封面。相册照片按比例缩至最长 1024 px，修正方向，保存到内部目录，原照片移动后仍可使用；选图取消不改变封面，读取失败保留原封面。
- 原有系统无衬线、系统衬线、等宽字体保留，新增楷体（[霞鹜文楷 1.522](https://github.com/lxgw/LxgwWenKai/releases/tag/v1.522)）、宋体（[思源宋体 2.003 简体区域版](https://github.com/adobe-fonts/source-han-serif/releases/tag/2.003R)）和仿宋（[朱雀仿宋 0.212，上游预览版](https://github.com/TrionesType/zhuque/releases/tag/v0.212)）。使用未经修改的官方字体文件，随 APK 离线提供；许可位于 `app/src/main/assets/font-licenses/`，也可在歌词设置查看。缺失字形由系统回退。桌面字体检查预览为 `../dist/font-preview.png`，不是 Android 界面截图。
- JSON 备份保存封面图案和新字体设置。照片不写入 JSON，换手机后重新选择。已有歌单、排序、音乐索引兼容；版本号 4，包名和签名延续旧版。

## 当前限制

- 系统锁屏媒体控件由 Android / HyperOS 管理。本版设置提供系统通知设置入口，未实现独立隐藏锁屏控件的应用开关；后台播放不能通过简单隐藏通知来保留同等控制能力。[Android 官方后台播放说明](https://developer.android.com/media/media3/session/background-playback)。
- 应用未运行或系统休眠时不持续扫描；再进入主动检查。监测是通知加轮询，不能承诺所有提供者即时上报。
- 不伪造逐字歌词；当前按普通 LRC 逐行展示。M4A 等格式可读取系统支持的基础标签，内嵌歌词读取目前以 FLAC/MP3 为主，其余可配同名 LRC。
- 不保证所有音频编码、码率和异常文件均可解码；尚未进行 100 GB 真实音乐库的性能实测。
- 跨手机自动匹配依赖唯一的文件名和大小；重名同大小的多文件不会自动合并。改名、更换提供者可能形成新文档编号；跨提供者同一文件的去重仍需实测完善。
- 新手机恢复备份后需重新授权。背景与歌单照片另行导入。安卓备份格式与旧网页原型备份格式不同。

## 构建与后续升级

固定应用 ID：`com.xiaohonghua.music`。本版面向个人安装，Release 沿用 0.1.x 的本地签名身份；签名配置和密钥文件中的 `debug` 是历史命名，最终 APK 已关闭调试。密钥在 `signing/xiaohonghua-debug.jks`（已排除出版本控制），请保留并私下备份。后续版本保持相同签名并递增版本号才能继续覆盖安装；卸载会删除内部数据。[Android 签名与更新说明](https://developer.android.com/studio/publish/app-signing)。

在 Android Studio 打开此 `android/` 目录，配置 JDK 17 与 Android SDK 36。当前电脑工具已放在项目 `../.toolchain/`，不要求全局安装。

从项目根目录执行本机已配置的构建：

```text
node tools/build-android.cjs :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease
node tools/package-android.cjs
```

公开源码的标准入口：在本目录运行 `gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`（macOS / Linux 使用 `bash gradlew`）。没有正式密钥时，Debug 使用标准开发签名；`assembleRelease` 生成未签名包，需配置自己的签名后分发，不会自动使用新 Debug 密钥替代正式签名。自行构建的不同签名包不能覆盖官方 APK。需要正确的 JDK/SDK 路径；构建工具和依赖初次下载需要联网，播放器运行无需联网。原工作区的构建助手在缺失密钥时会拒绝 Release 构建，避免意外生成不同签名。

SQLite 当前 schema 1；未来结构升级必须新增迁移，不能删库重建。GitHub 提供 APK 直接下载；商店上架仍需单独确定商店签名与更新迁移方案。
